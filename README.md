An evidence-first Codex Skill for reproducing computational claims from research papers with code, data, and experiments.

V1 closes a dangerous reproducibility gap: a successful command plus a hand-written metric can no longer produce a positive result. A claim is reproduced only when a machine extractor reads the value from a log or result artifact generated by the bound run, every required command succeeds, repository and policy checks remain valid, and a fresh comparison satisfies the predeclared policy.

> This result verifies only the declared computational claim under the recorded environment and protocol.

## Why Codex

Research reproduction requires both semantic reasoning and deterministic verification.

Codex is used to:

- read the paper as a whole;
- identify executable claims and their locations;
- map claims to official repositories, datasets, and commands;
- draft a reviewable, preview-only reproduction plan;
- diagnose failed or divergent runs;
- propose regression tests and documentation updates.

Codex does not assign scientific truth. The bundled deterministic runtime controls execution, extracts observations, verifies provenance, recomputes comparisons, and renders the final claim-scoped report.

The [Codex planning evaluation pilot](docs/codex-evaluation/README.md) publishes three paper/repository cases with initial prompts, draft plans, review records, revised plans, evidence links, and honest telemetry limitations. It is a pilot from the Codex desktop workflow, not an independently human-reviewed benchmark.

## Public evidence

The repository includes [15 public, paper-linked, low-cost, claim-level executable cases](benchmarks/benchmark-report.md) from Nature, Nature Methods, JMLR, KDD, NeurIPS, ICML, Journal of Financial Economics, and Mathematical Programming Computation, plus influential peer-reviewed research-software venues.

<!-- benchmark-facts:start -->
- 15 public, paper-linked, claim-level executable cases.
- 15/15 claims reproduced within their declared tolerance.
- 15/15 evidence bundles pass full artifact re-hashing and report recomputation.
- 0 deterministic-runtime API tokens and $0 estimated external API cost.
<!-- benchmark-facts:end -->
- 0 GPUs were requested by every benchmark plan.
- Every case publishes its paper/code links, plan, environment lock, data/license note, raw logs, observation, comparison, report, provenance, and scope limitations.

These are bounded claim-level executable checks. They do not pretend to rerun every large-scale experiment or validate every scientific conclusion in the linked papers.

## What V1 enforces

- **Run-derived observations:** stdout/stderr regex or JSONPath; JSON, CSV, NumPy, and Parquet result files; extractor version, expression, raw/normalized value, unit, command, log/file hash, run-record hash, and extraction time.
- **No manual promotion:** a manually read table, plot, or image is always `MANUAL_REVIEW_REQUIRED`.
- **Code-version binding:** full file-tree SHA-256, Git commit, scoped dirty-diff hash, submodules, explicit exclusions with reasons, and separate code/data/weight/config/environment hashes before and after execution.
- **Isolated execution:** copy, detached Git worktree, or Docker container mode. The original repository is checked before and after. Undeclared writes invalidate evidence.
- **Capability budgets:** wall/CPU time, memory, disk, output count, single-file size, GPU count, network policy, and write paths are declared per plan and can be narrowed per command.
- **Secret references:** plans contain `secret_ref`, never credentials. Recorded argv uses `[SECRET_REF:NAME]`; child environments are allowlisted; argv, logs, URLs, headers, and errors share redaction.
- **Evidence-bundle verification:** modifying a tracked artifact without updating provenance causes verification failure. The report generator re-reads raw evidence and recomputes the comparison; it never trusts a stored verdict.
- **Explicit statistics:** `all`/`any` tolerance composition, scalar/array/table comparison, unit conversion, multi-run mean/std, 95% equivalence intervals, non-inferiority, exact order, and Spearman correlation.

SHA-256 proves byte equality, not authorship. V1 deliberately does not claim that unsigned provenance prevents an attacker from rewriting both artifacts and the manifest. DSSE, Sigstore, RO-Crate, and in-toto/SLSA-style attestations remain future work.

## Install as a Codex Skill

Copy `skills/reproduce-research-paper` into a repository-level `.codex/skills/` directory or your personal Codex Skills directory. Then ask:

```text
Use $reproduce-research-paper to read this entire paper, identify its executable claims,
inventory the official repository, and create a preview-only reproduction plan.
Do not download data or execute experiments until I approve the plan and budget.
```

## Offline demo

Python 3.10+ and the standard library are sufficient for the Skill runtime. The bundled toy case uses no network.

```powershell
python skills/reproduce-research-paper/scripts/validate_reproduction_plan.py `
  --plan skills/reproduce-research-paper/assets/examples/reproduction-plan.json

python skills/reproduce-research-paper/scripts/run_reproduction.py `
  --plan skills/reproduce-research-paper/assets/examples/reproduction-plan.json `
  --output reproduction-output
```

The second command is preview-only. After reviewing the exact argv, isolation mode, network decision, write paths, and budgets:

```powershell
python skills/reproduce-research-paper/scripts/run_reproduction.py `
  --plan skills/reproduce-research-paper/assets/examples/reproduction-plan.json `
  --output reproduction-output `
  --execute

python skills/reproduce-research-paper/scripts/build_report.py `
  --bundle reproduction-output
```

The final command verifies provenance, observation source hashes, plan/run/inventory/environment bindings, a fresh comparison, and a fresh report rendering.

## Evidence bundle

```text
evidence-bundle/
├── plan.json
├── inventory-before.json
├── inventory-after.json
├── environment.json
├── run-record.json
├── observations.json
├── comparison.json
├── report.md
├── provenance.json
├── logs/
├── evidence-sources/
└── outputs/
```

Positive and negative statuses are claim-scoped:

- `CLAIM_REPRODUCED_WITHIN_TOLERANCE`
- `CLAIM_NOT_REPRODUCED`
- `PARTIALLY_REPRODUCED`
- `INCONCLUSIVE`
- `BLOCKED`
- `NOT_ATTEMPTED`
- `MANUAL_REVIEW_REQUIRED`

None means “the paper is true.” They describe only the declared computational claim under the recorded protocol.
