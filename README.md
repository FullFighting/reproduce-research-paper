An evidence-first Codex Skill for reproducing computational claims from research papers with code, data, and experiments.

V1.3 preserves the V1.2 evidence boundary and adds a maintainer-local, instrumented OpenAI API evaluation CLI, five real-source refusal/block/revision cases, independent-review and adjudication records, a malicious-research-material threat model, hardened Docker defaults, and a safe installer. A successful command plus a hand-written metric still cannot produce a positive result: a claim is reproduced only when a machine extractor reads the value from an artifact generated by the bound run, every required command succeeds, repository and policy checks remain valid, and a fresh comparison satisfies the predeclared policy.

> This result verifies only the declared computational claim under the recorded environment and protocol.

## Why Codex

Research reproduction requires both semantic reasoning and deterministic verification.

Codex is used to:

- read the paper as a whole;
- identify executable claims and their locations;
- map claims to official repositories, datasets, and commands;
- draft a reviewable, preview-only reproduction plan;
- diagnose failed or divergent runs;
- propose regression tests and documentation updates.

Codex does not assign scientific truth. The bundled deterministic runtime controls execution, extracts observations, verifies provenance, recomputes comparisons, and renders the final claim-scoped report.

The [Codex planning evaluation pilot](docs/codex-evaluation/README.md) publishes three paper/repository cases with initial prompts, draft plans, review records, revised plans, evidence links, and honest telemetry limitations. It is a pilot from the Codex desktop workflow, not an independently human-reviewed benchmark.

## Evidence runtime

- **Typed claims:** scalar, array, labeled table, ranking, categorical, string, artifact hash, and distribution expected values with type-compatible comparisons.
- **Extensible units:** validated symbol, scale, and semantic type support BLEU/ROUGE/F1, energy, throughput, currency, basis points, physical units, likelihoods, and custom metrics without source-code enums.
- **Run-derived observations:** stdout/stderr regex or JSONPath; JSON, CSV, NumPy, Parquet, and direct file-SHA-256 results; extractor version, expression, raw/normalized value, unit, command, source hash, run-record hash, and extraction time.
- **No manual promotion:** a manually read table, plot, or image is always `MANUAL_REVIEW_REQUIRED`.
- **Code-version binding:** full file-tree SHA-256, Git commit, scoped dirty-diff hash, submodules, explicit exclusions with reasons, and separate code/data/weight/config/environment hashes before and after execution.
- **Isolated execution:** copy, detached Git worktree, or Docker container mode. Container runs require digest-only images already present locally, drop all capabilities, forbid privilege escalation, select restricted seccomp, and use a non-root numeric user. The original repository is checked before and after. Undeclared writes invalidate evidence.
- **Capability budgets:** wall/CPU time, memory, disk, output count, single-file size, GPU count, network policy, and write paths are declared per plan and can be narrowed per command.
- **Secret-safe defaults:** environment `secret_bindings` are the default. Argv secret references are rejected unless an explicit high-risk compatibility mode is enabled and recorded; logs, URLs, headers, and errors share redaction.
- **Evidence-bundle verification:** modifying a tracked artifact without updating provenance causes verification failure. The report generator re-reads raw evidence and recomputes the comparison; it never trusts a stored verdict.
- **Explicit statistics:** `all`/`any` tolerance composition, scalar/array/table comparison, unit conversion, multi-run mean/std, 95% equivalence intervals, non-inferiority, exact order, and Spearman correlation.

SHA-256 proves byte equality, not authorship. Unsigned bundle provenance cannot prevent an attacker from rewriting both artifacts and the manifest. Release archives additionally publish checksums, an SPDX SBOM, local provenance, and GitHub build attestation; signed scientific-run provenance remains future work.

## Install as a Codex Skill

Use the standard-library installer, which performs an installation integrity check and validates the bundled plan after install:

```bash
python scripts/install_skill.py --scope user
python scripts/install_skill.py --scope repository --target /path/to/repository

python scripts/install_skill.py --action check --scope user
python scripts/install_skill.py --action update --scope user
python scripts/install_skill.py --action uninstall --scope user
python scripts/install_skill.py --action version
```

The installer records managed-file hashes, refuses to overwrite local changes by default, and removes only managed files. You can still copy `skills/reproduce-research-paper` manually into a repository-level `.codex/skills/` directory or your personal Codex Skills directory.

Then ask:

```text
Use $reproduce-research-paper to read this entire paper, identify its executable claims,
inventory the official repository, and create a preview-only reproduction plan.
Do not download data or execute experiments until I approve the plan and budget.
```

## Offline demo

Python 3.10+ and the standard library are sufficient for the Skill runtime. The bundled toy case uses no network.

Linux/macOS:

```bash
python3 skills/reproduce-research-paper/scripts/validate_reproduction_plan.py \
  --plan skills/reproduce-research-paper/assets/examples/reproduction-plan.json

python3 skills/reproduce-research-paper/scripts/run_reproduction.py \
  --plan skills/reproduce-research-paper/assets/examples/reproduction-plan.json \
  --output reproduction-output
```

Windows PowerShell:

```powershell
python skills/reproduce-research-paper/scripts/validate_reproduction_plan.py `
  --plan skills/reproduce-research-paper/assets/examples/reproduction-plan.json

python skills/reproduce-research-paper/scripts/run_reproduction.py `
  --plan skills/reproduce-research-paper/assets/examples/reproduction-plan.json `
  --output reproduction-output
```

The second command is preview-only. After reviewing the exact argv, isolation mode, network decision, write paths, and budgets:

```powershell
python skills/reproduce-research-paper/scripts/run_reproduction.py `
  --plan skills/reproduce-research-paper/assets/examples/reproduction-plan.json `
  --output reproduction-output `
  --execute

python skills/reproduce-research-paper/scripts/build_report.py `
  --bundle reproduction-output
```

The final command verifies provenance, observation source hashes, plan/run/inventory/environment bindings, a fresh comparison, and a fresh report rendering.

The [complete end-to-end demo transcript](docs/end-to-end-demo.md) continues through budget approval, isolated execution, evidence-bundle generation, and a tamper check that must fail.

## Maintainer-local OpenAI API evaluation

`evaluations/run_codex_evaluation.py` is a local CLI for maintainers, not a deployed API or public service. It reads the maintainer's key only from `OPENAI_API_KEY`, requires `--send` for a paid request, uses a fixed official Responses API endpoint with `store: false`, and never writes the key, request headers, Organization credentials, or environment variables to results.

```bash
python evaluations/run_codex_evaluation.py --validate-cases

python evaluations/run_codex_evaluation.py \
  --case mimic-iv-redistribution-prohibited \
  --model gpt-5.6-terra
```

A maintainer-controlled paid run additionally requires a local cost cap, output directory, exported key, and `--send`. It records the public input snapshot, prompt version and hash, requested and returned model IDs, tokens, estimated cost, latency, model-generated initial plan, pending human-review fields, and evidence-bundle binding status. It does not expose an endpoint that lets third parties consume grant credits.

See the [evaluation README](evaluations/README.md), [protocol](evaluations/protocol.md), [case schema](evaluations/case-schema.json), [telemetry schema](evaluations/telemetry-schema.json), [malicious-research-material threat model](docs/threat-model.md), and [independent reviewer call](docs/independent-review-call.md). Generated results are ignored by Git until a maintainer deliberately reviews and publishes a redacted set.

## Evidence bundle

```text
evidence-bundle/
├── plan.json
├── inventory-before.json
├── inventory-after.json
├── environment.json
├── run-record.json
├── observations.json
├── comparison.json
├── report.md
├── provenance.json
├── logs/
├── evidence-sources/
└── outputs/
```

Positive and negative statuses are claim-scoped:

- `CLAIM_REPRODUCED_WITHIN_TOLERANCE`
- `CLAIM_NOT_REPRODUCED`
- `PARTIALLY_REPRODUCED`
- `INCONCLUSIVE`
- `BLOCKED`
- `NOT_ATTEMPTED`
- `MANUAL_REVIEW_REQUIRED`

None means “the paper is true.” They describe only the declared computational claim under the recorded protocol.
